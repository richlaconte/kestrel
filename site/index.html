// Runs inside the host process, not the webview.
// Plain TypeScript. No Rust, no Node, no preload.

export function greet(args: { name: string }): string {
  return `Hello, ${args.name}! From inside the host.`;
}

export function visitCount(): number {
  const raw = hostReadFile("./kestrel-data.json");
  const data = raw.startsWith("ERR:") ? { visits: 0 } : JSON.parse(raw);
  data.visits += 1;
  hostWriteFile("./kestrel-data.json", JSON.stringify(data));
  return data.visits;
}
import { useState } from "react";
import { greet } from "../native-client"; // typed, generated

export default function App() {
  const [name, setName] = useState("");
  const [msg, setMsg] = useState("");
  return (
    <form onSubmit={async (e) => {
      e.preventDefault();
      setMsg(await greet({ name })); // Promise<string>
    }}>
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <button>Greet</button> <p>{msg}</p>
    </form>
  );
}

export function greet(args: { name: string }): Promise<string> {

Electron: 4 files to move one string

No main, preload, or renderer wiring.

In Electron, the security boilerplate becomes most of the app: ipcMain, contextBridge, channel-name strings, and a hand-written declare global to get types. In our measured app, ~50 of 117 lines existed only to cross the process boundary.

  • Export a function from native.ts. Import it in React.
  • The framework handles the bridge, the isolation, and the types.

Tauri: Rust for every native call

No Rust toolchain. No 8-minute first build.

Raw Tauri compiles a new Rust binary for every app. That's 1.6 GB of target/, a second build system, and a Rust recompile every time a native function changes. Kestrel ships one precompiled host per platform, configured at runtime by your kestrel.json.

  • Designed so app developers never install Rust. The host is built once per platform in CI.
  • One config file. No tauri.conf.json, no forge.config.ts.
  • One build command, so you never ship a silently broken release.

Both: IPC by magic string

IPC is a typed function call.

kestrel typegen reads your native.ts with the TypeScript compiler and generates exact client stubs, with real parameter and return types. Renames break at compile time, not in front of your users.

  • Regenerated automatically by kestrel dev.
  • Real HMR into the native window. Dev and prod use the same kestrel:// origin.

Electron: Node in the privileged process

Native code with least privilege built in.

Native functions run in an embedded QuickJS engine inside the host process. It adds only 0.8 MB and needs no Node sidecar. There is no ambient fs, fetch or child_process: your code can only touch the bindings the host grants, and the webview can't touch anything at all.

  • Permissions are declared in the manifest and enforced by the host.
  • Heavy compute can move to Rust plugins or WASM later behind the same protocol.

How it works

One prebuilt host. Your app is data.

Most Tauri apps compile a new Rust binary per app. Kestrel compiles Tauri v2 once per platform, in CI, and your app tells it what to do at runtime.

Manifest-driven host

Window, frontend, and native module are resolved from kestrel.json at launch. One binary runs any app with zero recompiles.

Same origin in dev and prod

In dev, the kestrel:// protocol reverse-proxies to Vite, so HMR, routing, and IPC policy behave the same as the built app.

Portable builds

kestrel build bundles the host, your frontend, and your compiled native module. It's 6.6 MB for the React template and runs from any directory.

Quickstart

Three commands to a native window.

Scaffold

A React + Vite + TypeScript app with a native module already wired.

npx create-kestrel-app my-app

Run

Opens a real native window with HMR. Typed stubs regenerate as you edit.

cd my-app && npm i && npm run dev

Build

A portable bundle you can copy anywhere and run.

npx kestrel build .

Pre-alpha note: the CLI doesn't download the prebuilt host automatically yet. Until it does, set KESTREL_HOST to a host binary from CI, or build one once from the repo with npm run build:host.

Honest status

Pre-alpha: the architecture is proven, the API is not stable yet.

Kestrel is early. This is exactly what works today and what is still to come, so you can decide whether to start using it now.

Works today

  • One shared host binary running any app from a manifest
  • React + Vite template with real HMR in the native window
  • Native functions in TypeScript with generated, typed client stubs
  • create · dev · typegen · build (unsigned portable bundle)
  • Host builds for Linux, macOS, and Windows in CI; end-to-end tested on Linux and macOS

On the roadmap

  • Signed installers and auto-update on top of build
  • Async native functions
  • The full kestrel/native std-lib: fs, dialog, notify, store, clipboard (RFC-0001)
  • Automatic prebuilt-host download (no local Rust build, even for contributors)
  • Rust / WASM plugin API for heavy compute
FAQ

Questions, answered

Is Kestrel a fork of Tauri?

No. Kestrel is a developer-experience layer on top of Tauri v2. It uses Tauri's runtime and the system webview, but replaces the per-app Rust project with one prebuilt host plus a TypeScript-only CLI, manifest, and native-function model.

When should I still pick Electron?

When you need pixel-identical rendering on every OS (Electron ships the same Chromium everywhere), deep Node.js or npm-native-module access in the privileged process, or production-grade signing and auto-update today. Electron's DX is the bar Kestrel set out to match. Its footprint is what Kestrel improves on.

Do I need Rust installed?

The design goal is no. The host is compiled once per platform in CI, and your app is just a manifest, TypeScript, and static files. Today the CLI doesn't download that host for you yet, so you either point KESTREL_HOST at a CI-built binary or build it once with npm run build:host, which does need Rust. Automatic downloads are next on the roadmap.

Can native functions use npm packages or Node APIs?

Native functions run in QuickJS, so ES2023 is available but Node built-ins aren't. That is deliberate: privileged code only gets the capability-scoped bindings the host grants. Pure-JS packages that don't depend on Node can be bundled in. Your frontend can use anything that runs in a browser.

What about cross-platform rendering differences?

System webviews (WebKit on macOS and Linux, WebView2 on Windows) differ slightly. Kestrel documents those differences instead of hiding them, and runs the same headless smoke tests in CI that it uses to verify the host.

Is QuickJS fast enough?

For glue code, yes: a full webview → native → webview round-trip averages 0.81 ms. QuickJS has no JIT, so heavy number crunching belongs in Rust or WASM. The dispatch protocol is engine-agnostic, so that's an extension, not a rewrite.

Is it production-ready?

Not yet. Kestrel is pre-alpha and the API will change. It's great for prototypes, internal tools, and helping shape the API. Watch the repo or follow RFC-0001 to weigh in.
